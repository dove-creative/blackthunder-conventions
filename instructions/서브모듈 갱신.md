# 서브모듈 갱신

## 목적

이 문서는 BlackThunder Conventions처럼 여러 저장소가 서브모듈로 사용하는 저장소를 갱신하는 절차를 정리한다.

갱신은 예약이나 자동 감지 없이, 필요할 때 갱신 봇에 명령해 실행한다. 봇은 서브모듈이 가리키는 커밋만 갱신한다. 바뀐 규칙에 맞춰 코드나 문서를 고치는 일은 갱신 PR에서 따로 한다.

## 갱신 봇

갱신 봇은 비공개 저장소 `dove-creative/repo-bot`의 Update submodule 워크플로이다. GitHub App이 설치된 저장소마다 `.gitmodules`를 읽어 원본 저장소를 사용하는 서브모듈을 찾으므로, 대상 저장소 목록을 따로 관리하지 않는다.

```bash
gh workflow run update-submodule.yml --repo dove-creative/repo-bot -f source=blackthunder-conventions -f mode=pr
```

| `mode` | 동작 |
|---|---|
| `check` | 대상 저장소와 현재 커밋을 확인만 한다. |
| `pr` | 갱신 PR을 열거나, 열려 있는 갱신 PR에 이어서 커밋한다. |
| `push` | 대상 저장소의 기본 브랜치에 바로 반영한다. |

`targets`에 저장소 이름을 쉼표로 구분해 넣으면 해당 저장소만 갱신한다. 입력과 설정의 자세한 내용은 봇 저장소의 README를 따른다.

## 사용 저장소 추가

새 저장소가 서브모듈을 사용하기 시작하면 봇이 사용하는 GitHub App의 설치 대상에 그 저장소를 추가한다. 사용 저장소에는 워크플로나 시크릿을 두지 않는다.

## 갱신 PR 처리

- PR 본문의 커밋 링크에서 원본 저장소의 변경 내용을 확인한다.
- 바뀐 규칙에 맞춰 코드나 문서를 고쳐야 하면 같은 PR 브랜치에 커밋한다. PR이 열려 있는 동안 봇을 다시 실행하면 그 브랜치 위에 이어서 커밋하므로 추가한 커밋이 유지된다.
- 고칠 내용이 없으면 저장소의 검증을 확인한 뒤 병합한다.
- 병합한 뒤 로컬 저장소는 `git pull`과 `git submodule update`로 맞춘다.

## 검증 기준

- 서브모듈을 사용하는 모든 저장소가 GitHub App의 설치 대상에 포함되어 있는가
- 갱신 전에 `check` 모드로 대상 저장소와 현재 커밋을 확인했는가
- 갱신 PR에 서브모듈 외의 의도하지 않은 변경이 없는가
