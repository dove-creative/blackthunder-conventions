# 서브모듈 갱신

## 목적

이 문서는 BlackThunder Conventions를 서브모듈로 사용하는 저장소가 컨벤션 변경을 자동으로 받도록 설정하는 기준을 정리한다.

자동화는 서브모듈이 가리키는 커밋만 갱신한다. 바뀐 규칙에 맞춰 코드나 문서를 고치는 일은 갱신 PR에서 따로 한다.

## 동작 방식

두 경로를 함께 사용한다.

| 경로 | 시점 | 필요한 설정 |
|---|---|---|
| 갱신 이벤트 | 컨벤션 저장소의 `main`이 바뀌는 즉시 | GitHub App, 양쪽 저장소의 워크플로 |
| Dependabot | 매주 | 사용 저장소의 `.github/dependabot.yml` |

1. 컨벤션 저장소의 `main`에 푸시하면 `.github/workflows/notify-consumers.yml`이 사용 저장소마다 `conventions-updated` 이벤트를 보낸다.
2. 사용 저장소의 `.github/workflows/update-conventions.yml`이 서브모듈을 컨벤션 저장소의 최신 `main`으로 올리고, `chore/conventions-update` 브랜치로 PR을 열거나 갱신한다.
3. 갱신 이벤트가 오지 않았다면 Dependabot이 매주 서브모듈 갱신 PR을 연다. 이미 최신이면 Dependabot은 PR을 만들지 않는다.

갱신 워크플로는 `.gitmodules`에서 URL이 `blackthunder-conventions`로 끝나는 서브모듈을 찾으므로 서브모듈 경로와 관계없이 같은 파일을 사용한다.

## GitHub App 설정

갱신 이벤트를 보내고 PR을 만들 때는 GitHub App 토큰을 사용한다. 기본 `GITHUB_TOKEN`으로 만든 PR에서는 저장소의 CI가 실행되지 않는다.

1. GitHub의 Developer settings에서 GitHub App을 만든다. 외부 알림을 받을 필요가 없으므로 Webhook은 끈다.
2. Repository permissions에서 Contents와 Pull requests를 Read and write로 지정한다.
3. 개인 키를 만들고, 앱을 모든 사용 저장소에 설치한다. 컨벤션 저장소에는 설치하지 않아도 된다.
4. 컨벤션 저장소와 모든 사용 저장소의 Settings > Secrets and variables > Actions에 아래 값을 등록한다.

| 이름 | 종류 | 값 |
|---|---|---|
| `CONVENTIONS_APP_ID` | Variable | GitHub App의 App ID |
| `CONVENTIONS_APP_PRIVATE_KEY` | Secret | 개인 키 파일의 내용 |

컨벤션 저장소에 값이 없으면 알림 워크플로는 경고만 남기고 끝나며, 사용 저장소는 Dependabot 갱신만 받는다.

## 사용 저장소 추가

새 저장소가 컨벤션을 서브모듈로 사용하기 시작하면 아래를 함께 한다.

1. 컨벤션 저장소 `notify-consumers.yml`의 `CONSUMERS`에 저장소 이름을 추가한다.
2. GitHub App을 새 저장소에 설치하고, 앞 절의 변수와 시크릿을 등록한다.
3. 새 저장소에 아래 두 파일을 추가한다.

### Dependabot 설정

`.github/dependabot.yml`:

```yaml
version: 2
updates:
  # Weekly fallback when the conventions repository cannot send update events.
  - package-ecosystem: "gitsubmodule"
    directory: "/"
    schedule:
      interval: "weekly"
```

### 갱신 워크플로

`.github/workflows/update-conventions.yml`:

```yaml
name: Update conventions

on:
  repository_dispatch:
    types: [conventions-updated]
  workflow_dispatch:

permissions:
  contents: read

concurrency:
  group: update-conventions
  cancel-in-progress: false

jobs:
  update:
    name: Update conventions submodule
    runs-on: ubuntu-latest
    timeout-minutes: 10
    env:
      BRANCH: chore/conventions-update
    steps:
      - name: Check app credentials
        env:
          APP_ID: ${{ vars.CONVENTIONS_APP_ID }}
          PRIVATE_KEY: ${{ secrets.CONVENTIONS_APP_PRIVATE_KEY }}
        run: |
          if [ -z "$APP_ID" ] || [ -z "$PRIVATE_KEY" ]; then
            echo "::error::Set the CONVENTIONS_APP_ID variable and the CONVENTIONS_APP_PRIVATE_KEY secret."
            exit 1
          fi

      # An app token lets the pull request trigger the repository's own workflows.
      - name: Create app token
        id: token
        uses: actions/create-github-app-token@v2
        with:
          app-id: ${{ vars.CONVENTIONS_APP_ID }}
          private-key: ${{ secrets.CONVENTIONS_APP_PRIVATE_KEY }}

      - name: Check out source
        uses: actions/checkout@v7
        with:
          token: ${{ steps.token.outputs.token }}

      - name: Update submodule and pull request
        env:
          GH_TOKEN: ${{ steps.token.outputs.token }}
          BASE: ${{ github.event.repository.default_branch }}
        run: |
          name=$(git config -f .gitmodules --get-regexp '^submodule\..*\.url$' \
            | awk '$2 ~ /\/blackthunder-conventions(\.git)?$/ { print $1; exit }')
          if [ -z "$name" ]; then
            echo "::error::No blackthunder-conventions submodule is registered in .gitmodules."
            exit 1
          fi
          name=${name#submodule.}
          name=${name%.url}
          path=$(git config -f .gitmodules "submodule.$name.path")

          # Continue an open pull request so commits added to it are kept; otherwise start from the base branch.
          pr=$(gh pr list --head "$BRANCH" --state open --json number --jq '.[0].number')
          if [ -n "$pr" ]; then
            git fetch origin "$BRANCH"
            git switch -c "$BRANCH" FETCH_HEAD
          else
            git switch -c "$BRANCH"
          fi

          git submodule update --init --remote "$path"
          if git diff --quiet -- "$path"; then
            echo "The conventions submodule is already up to date."
            exit 0
          fi

          sha=$(git -C "$path" rev-parse HEAD)
          short=${sha:0:7}
          title="Update BlackThunder Conventions to $short"
          body="Updates \`$path\` to [\`$short\`](https://github.com/dove-creative/blackthunder-conventions/commit/$sha), the latest \`main\` of BlackThunder Conventions.

          Review the changed conventions and apply any code or document changes they require before merging. Commits added to this branch are kept when later updates arrive."

          git config user.name "github-actions[bot]"
          git config user.email "41898282+github-actions[bot]@users.noreply.github.com"
          git add "$path"
          git commit -m "$title"

          if [ -n "$pr" ]; then
            git push origin "$BRANCH"
            gh pr edit "$pr" --title "$title" --body "$body"
          else
            git push --force origin "$BRANCH"
            gh pr create --base "$BASE" --head "$BRANCH" --title "$title" --body "$body"
          fi
```

## 갱신 PR 처리

- PR 본문의 커밋 링크에서 바뀐 컨벤션을 확인한다.
- 규칙 변경에 맞춰 코드나 문서를 고쳐야 하면 같은 PR 브랜치에 커밋한다. PR이 열려 있는 동안에는 다음 갱신도 그 브랜치 위에 이어서 커밋되므로 추가한 커밋이 유지된다.
- 고칠 내용이 없으면 저장소의 검증을 확인한 뒤 병합한다.
- 갱신 이벤트 PR과 Dependabot PR이 함께 열렸다면 하나를 병합하고 나머지는 닫는다.

## 검증 기준

- 컨벤션 저장소 `notify-consumers.yml`의 `CONSUMERS`가 서브모듈을 사용하는 저장소 목록과 일치하는가
- 모든 사용 저장소에 GitHub App이 설치되어 있는가
- 컨벤션 저장소와 모든 사용 저장소에 변수와 시크릿이 등록되어 있는가
- 모든 사용 저장소에 `.github/dependabot.yml`과 `.github/workflows/update-conventions.yml`이 있는가
- 컨벤션 저장소에 푸시한 뒤 각 사용 저장소에 갱신 PR이 열리는가
