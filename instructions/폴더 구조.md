# 폴더 구조

## 목적

이 문서는 프로젝트의 소스 코드, 일반 문서, 예시, 테스트와 작업 지침을 폴더별로 배치하고 관리하는 기준을 정리한다.

## 기본 원칙

- 파일은 역할에 따라 배치하며, 관련된 코드와 문서의 관계를 쉽게 찾을 수 있도록 구성한다.
- 프로젝트 지침과 언어·플랫폼·빌드 도구가 요구하는 구조를 우선한다. 아래 구조는 일반적인 코드 저장소의 기준이며, 모든 프로젝트에 같은 폴더 구성을 강제하지 않는다.
- 실제로 관리할 내용이 있는 폴더만 만든다. 빈 폴더를 미리 만들거나 한두 파일을 위해 불필요한 계층을 추가하지 않는다.
- 폴더와 파일 이름의 표기는 [네이밍](네이밍.md)과 해당 언어의 컨벤션을 따른다.

## 대표 폴더

| 폴더 | 역할 | 주요 내용 |
| --- | --- | --- |
| `src` | 제품이나 라이브러리의 구현 | 배포하거나 실제 서비스에서 사용하는 소스 코드와 프로젝트 파일 |
| `docs` | 프로젝트의 일반 문서 | 개요, 설계, 구현 기준, 사용법, API 설명과 문서용 자료 |
| `samples` | 기능의 사용 예시 | 사용자가 실행하고 따라 할 수 있는 예시 프로젝트와 실행 안내 |
| `tests` | 동작 검증 | 테스트 코드, 테스트 데이터, 테스트 문서와 보조 도구 |
| `guidelines` | 작업 기준 | 프로젝트에서 참조하는 컨벤션, 작업 지침과 공유 지침 서브모듈 |

## 소스 코드

`src`에는 제품이나 라이브러리의 실제 구현을 둔다. 여러 소스 프로젝트가 있다면 프로젝트별 하위 폴더로 구분한다.

사용법을 보여주는 예시는 `samples`에, 동작을 검증하는 테스트는 `tests`에 두어 각 코드의 목적이 경로에 드러나도록 한다.

## 일반 문서

`docs`에는 프로젝트의 목적과 구조를 설명하는 개요 문서, 설계와 구현 기준, 사용법과 API 문서 등을 둔다. 문서에 사용하는 이미지와 첨부 자료도 관련 문서에서 찾기 쉬운 위치에 함께 관리한다.

저장소 루트의 `README.md`는 프로젝트를 처음 접하는 사람을 위한 진입 문서로 두고, 자세한 내용은 `docs`의 해당 문서로 연결한다. 문서별 역할과 작성 방식은 [문서 양식](문서%20양식.md)과 [문서 컨벤션](../conventions/01.%20dove%20Documentation%20Convention.md)을 따른다.

테스트 계획과 실행 기록은 아래 테스트 문서 절의 위치 기준을 따른다.

## 예시 프로젝트

`samples`에는 사용자가 기능을 이해하고 자신의 프로젝트에 적용할 수 있도록 대표 사용 흐름을 보여주는 예시 프로젝트를 둔다.

예시 프로젝트가 하나라면 `samples` 바로 아래에 두고, 독립적으로 실행되는 예시가 여러 개라면 프로젝트별 하위 폴더로 구분한다. 각 예시에는 목적, 실행 방법과 출력물 위치를 설명하는 `README.md`를 둔다. 구체적인 구성과 실행 방식은 [예시 프로젝트](예시%20프로젝트.md)를 따른다.

## 테스트

`tests`에는 기능이 정해진 기준대로 동작하는지 검증하는 테스트 코드와 필요한 테스트 데이터를 둔다. 테스트 프로젝트나 검증 대상이 여러 개라면 해당 단위로 하위 폴더를 구분한다.

테스트 데이터와 보조 파일은 이를 사용하는 테스트와의 관계가 드러나는 위치에 둔다. 여러 테스트가 공유하는 파일은 공통으로 참조할 수 있는 위치에서 관리한다.

### 테스트 문서

테스트 계획과 실행 기록은 해당 테스트 코드가 위치한 폴더 아래의 `docs` 하위 폴더에 함께 둔다. 문서가 다루는 테스트 코드가 여러 폴더에 나뉘어 있다면, 그 폴더들의 가장 가까운 공통 상위 폴더 아래의 `docs`에 둔다.

### 테스트 보조 스크립트

테스트 보조 스크립트 중 재사용 가능한 스크립트는 해당 테스트 문서와 같은 폴더에 두는 것을 권장한다. 같은 폴더에 두기 어려운 경우에는 저장소 루트의 `tests/tools`에 둔다. 일회성 테스트 보조 스크립트는 사용이 끝난 즉시 삭제한다.

## 작업 지침

`guidelines`에는 개발과 문서 작업에 적용할 컨벤션과 작업 지침을 둔다. 여러 프로젝트에서 공유하는 지침은 서브모듈 등 기존의 공유 방식으로 참조한다.

프로젝트 루트의 `AGENTS.md`에는 작업에 필요한 지침의 위치와 적용 기준을 안내한다. 프로젝트의 기능과 설계를 설명하는 문서는 `docs`에서 관리한다.
