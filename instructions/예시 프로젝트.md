## 1. 목적

이 문서는 패키지에 포함하는 C# 예시 프로젝트를 어떤 기준으로 구성할지 정리한다.

예시 프로젝트는 사용자가 기능을 처음 이해하고, 같은 기능을 자기 프로젝트에 옮겨 볼 수 있게 하는 공개 표면이다. 따라서 예시 코드는 단순히 동작하는 코드가 아니라, 패키지가 권장하는 사용 흐름을 보여주는 기준 코드여야 한다.

## 2. 기본 원칙

- 예시 프로젝트는 사용자가 패키지의 핵심 기능을 짧은 시간 안에 실행하고 이해할 수 있도록 구성한다.
- 예시 프로젝트는 실제 사용자가 패키지를 참조하는 방식으로 패키지 기능을 사용한다.
- 예시 프로젝트는 `dotnet run`으로 실행할 수 있는 콘솔 앱을 기본으로 한다.
- 인자 없이 실행하면 `sample>` 프롬프트를 열고 사용자가 명령을 반복하여 실행할 수 있게 한다.
- 명령 인자가 있으면 해당 명령을 한 번 실행하고 종료하여 자동 검증이 가능하게 한다.
- 예시 코드의 출력은 사용자가 읽기 쉬워야 하며, 기능 이해에 필요하지 않은 로그로 콘솔을 어지럽히지 않는다.
- 로그, 리포트, 결과 파일은 예시 실행 파일의 출력 디렉터리 아래에 모은다.
- 저장소 구조를 나타내는 `samples` 디렉터리는 소문자를 사용하고, 그 아래 프로젝트, 폴더, 소스 파일은 PascalCase를 사용한다.

## 3. C# 예시 프로젝트 구조

C# 예시 프로젝트가 하나라면 저장소의 `samples` 바로 아래에 둔다.

기본 구조는 아래와 같다.

```text
samples/
├─ Program.cs
├─ README.md
├─ ProductName.Samples.csproj
└─ Scenarios/
   ├─ BasicSample.cs
   └─ AdvancedSample.cs
```

서로 독립적으로 실행되는 예시 프로젝트가 여러 개라면 그때 `samples/FeatureA`, `samples/FeatureB`처럼 프로젝트별 하위 폴더를 추가한다.

각 파일과 폴더의 역할은 다음과 같다.

| 파일 또는 폴더 | 역할 |
| --- | --- |
| `Program.cs` | 콘솔 앱의 진입점과 명령 라우팅 |
| `README.md` | 예시의 목적, 실행 명령, 사용 가능한 명령, 출력물 위치 |
| `.csproj` | 예시 프로젝트의 빌드 설정과 패키지 참조 |
| `Scenarios` | 명령별 사용 예시와 필요한 도메인 모델 |

시나리오가 하나뿐이거나 코드가 짧다면 별도의 `Scenarios` 폴더 없이 `Program.cs`와 하나의 예시 파일만 둘 수 있다. 시나리오가 여러 개라면 `BasicSample.cs`, `AdvancedSample.cs`처럼 역할이 드러나는 파일로 분리한다.

솔루션 파일은 예시가 여러 프로젝트로 구성되거나 IDE에서 별도로 열어야 할 필요가 있을 때만 추가한다. 공통 실행 환경 클래스도 여러 시나리오가 실제로 공유하는 초기화나 상태가 있을 때만 둔다.

## 4. 프로젝트 설정

예시 프로젝트의 `.csproj`는 콘솔 실행에 필요한 최소 설정만 명시한다. 대상 프레임워크는 패키지가 지원하는 범위 안에서 선택하며, 언어 버전과 nullable 설정 등은 저장소의 공통 설정을 따르는 것을 기본으로 한다.

```xml
<Project Sdk="Microsoft.NET.Sdk">
  <PropertyGroup>
    <OutputType>Exe</OutputType>
    <TargetFramework>net9.0</TargetFramework>
  </PropertyGroup>

  <ItemGroup>
    <ProjectReference Include="../src/ProductName/ProductName.csproj" />
  </ItemGroup>
</Project>
```

같은 저장소의 현재 소스를 사용하는 예시는 `ProjectReference`를 사용한다. 이를 통해 패키지의 변경 사항이 예시에 바로 반영되고, 예시와 실제 API의 불일치를 빌드 과정에서 확인할 수 있다.

배포된 패키지를 소비하는 흐름 자체를 검증하는 예시는 `PackageReference`를 사용한다.

```xml
<ItemGroup>
  <PackageReference Include="Company.Product" Version="1.0.0" />
</ItemGroup>
```

패키지 소스 파일을 `Compile Include`로 직접 링크하는 방식은 실제 사용자의 참조 방식과 다르므로 사용하지 않는다. 특정 프로젝트만 다른 언어 버전이나 nullable 설정이 필요하다면 해당 값을 명시하고 README에 그 이유를 설명한다.

## 5. 진입점과 실행 방식

`Program.cs`는 예시 프로젝트의 유일한 콘솔 진입점이다.

진입점은 아래 흐름을 따른다.

1. 명령과 필요한 실행 환경을 초기화한다.
2. CLI 인자가 있으면 첫 번째 인자를 명령으로, 나머지 인자를 해당 명령의 인자로 전달한다.
3. 전달된 명령을 한 번 실행하고 결과에 맞는 종료 코드를 반환한다.
4. CLI 인자가 없으면 사용 가능한 명령을 출력하고 `sample>` 프롬프트를 연다.
5. 빈 입력은 무시하고 다시 입력을 기다린다.
6. `Help`는 사용 가능한 명령과 간단한 설명을 출력한다.
7. `Exit`는 대화형 예시를 종료한다.

동기 예시는 `int Main(string[] args)`를 사용할 수 있고, 비동기 API를 보여주는 예시는 `Task<int> Main(string[] args)`를 사용할 수 있다.

대화형 실행 중 예상하지 못한 예외가 발생하면 콘솔에 오류를 출력하고 프롬프트 루프는 유지한다. 명령 인자를 사용한 일회 실행에서 예외가 발생하면 콘솔 오류 스트림에 내용을 출력하고 0이 아닌 종료 코드를 반환한다.

예외 자체를 보여주는 시나리오처럼 예외가 의도된 결과인 경우에는 시나리오 안에서 이를 처리하고 의도된 결과임을 명확히 출력한다.

## 6. 실행 환경과 출력

공통 실행 환경 클래스는 필수 요소가 아니다. 여러 시나리오에서 아래 책임을 공유하는 경우에만 추가한다.

- 출력 경로 정의와 출력 디렉터리 생성
- 패키지 실행 환경 초기화와 정리
- 시나리오가 공유하는 설정과 상수 보관

결과 파일은 예시의 목적상 필요한 경우에만 생성한다. 기본 출력 경로는 `AppContext.BaseDirectory` 아래의 `SampleOutput`으로 둔다.

예:

```csharp
private static readonly string _outputDirectory
    = Path.Combine(AppContext.BaseDirectory, "SampleOutput");
```

파일을 생성하기 전에는 출력 디렉터리가 존재하는지 확인하고, 생성되는 파일의 종류와 위치를 README에 적는다. 예시 실행만으로 저장소의 소스 디렉터리에 결과 파일이 생기지 않도록 한다.

패키지가 로그 기능을 제공한다면 콘솔 출력은 대표 동작과 결과를 이해하는 데 필요한 수준으로 제한한다. 도메인 객체 내부의 세부 로그를 기본 출력으로 노출하지 않는다.

## 7. 사용 방법 문서

각 예시 프로젝트에는 `README.md`를 둔다.

README에는 아래 내용을 포함한다.

1. 예시가 무엇을 보여주는지 한 문장으로 설명한다.
2. 대화형 실행 명령과 일회 실행 명령을 적는다.
3. 사용 가능한 명령과 각 명령의 목적을 적는다.
4. 결과 파일을 생성한다면 저장 위치를 적는다.

기본 형식은 아래와 같다.

````markdown
# 기본 사용 예시

이 예시는 패키지의 기본 사용 흐름과 결과를 보여준다.

## 실행

대화형 프롬프트를 실행한다.

```powershell
dotnet run --project ProductName.Samples.csproj
```

대표 시나리오를 한 번 실행하고 종료한다.

```powershell
dotnet run --project ProductName.Samples.csproj -- basic
```

## 명령

```text
basic
advanced
export-report
help
exit
```

## 출력

결과 파일은 예시 실행 파일의 `SampleOutput` 디렉터리에 저장된다.
````

README는 예시 실행에 필요한 최소 사용법을 담는 문서이다. API 전체 설명이나 긴 튜토리얼은 별도의 Usage 문서나 API 문서에 둔다.

## 8. 검증 기준

C# 예시 프로젝트를 추가하거나 수정할 때는 아래를 확인한다.

- 필요한 경우 먼저 `dotnet restore samples/ProductName.Samples.csproj`를 실행한다.
- `dotnet build samples/ProductName.Samples.csproj --no-restore`가 통과하는지 확인한다.
- `dotnet run --project samples/ProductName.Samples.csproj -- help`가 명령 목록을 출력하고 종료 코드 0으로 끝나는지 확인한다.
- 대표 명령을 `dotnet run --project samples/ProductName.Samples.csproj -- basic`으로 실행하여 예상한 결과와 종료 코드를 확인한다.
- 인자 없이 실행했을 때 `sample>` 프롬프트가 열리고, 빈 입력, `help`, `exit`가 정해진 방식으로 동작하는지 확인한다.
- 알 수 없는 명령이나 예상하지 못한 예외가 일회 실행에서 0이 아닌 종료 코드를 반환하는지 확인한다.
- README의 실행 명령, 명령 목록, 출력 위치가 실제 동작과 일치하는지 확인한다.
- 빌드가 만든 `bin`, `obj`와 예시가 생성한 결과 파일을 저장소 소스에 남기지 않는다.

C# 예시 프로젝트는 `dotnet run`으로 쉽게 실행할 수 있는 작은 콘솔 앱이어야 한다. 사용자는 `sample>` 프롬프트에서 여러 명령을 실행하거나 명령 인자로 대표 시나리오를 한 번 실행하고, 필요하다면 `SampleOutput`에서 결과를 확인할 수 있어야 한다.
