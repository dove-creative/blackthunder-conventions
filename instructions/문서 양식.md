# 문서 양식

## 목적

이 문서는 마크다운 문서를 작성할 때 문서의 구조와 표기 방식의 기준을 정리한다.

문서의 제목 단계는 독자가 내용을 훑는 순서를 만든다. 따라서 제목은 문서 전체의 이름을 나타내는 `#` 하나로 시작하고, 본문 소항목은 `##`부터 단계적으로 내려가며 사용한다.

## 기본 원칙

- 마크다운 문서는 파일마다 하나의 `# 제목`으로 시작한다.
- `#` 제목은 문서 전체를 대표하는 이름으로 사용한다.
- 본문의 큰 소항목은 `##`부터 사용한다.
- 더 작은 소항목이 필요할 때만 `###`, `####`처럼 한 단계씩 내려간다.
- 제목 단계를 건너뛰지 않는다.
- 제목과 다른 제목 또는 본문 사이에는 빈 행을 한 줄 둔다.
- 파일은 개행 문자로 끝낸다.
- 제목 단계는 글자 크기 조절 용도가 아니라 문서 구조 표현 용도로 사용한다.

## 파일명

문서 파일명은 문서의 내용을 알아보기 쉬운 제목으로 작성한다.

- 순서나 분류를 나타내는 번호가 필요한 문서는 `00. 제목.md` 형식을 사용한다. 번호는 두 자리 숫자로 쓰고, 마침표 뒤에는 공백 한 칸을 둔다. 예: `00. Overview.md`, `02. Python Convention.md`
- 번호가 필요 없는 문서는 `제목.md` 형식을 사용한다. 예: `문서 양식.md`, `API Guide.md`
- 제목의 단어 사이는 공백으로 구분하며, 단어를 하이픈으로 잇는 케밥 표기는 사용하지 않는다. 예: `API Guide.md`를 사용하고 `api-guide.md`는 사용하지 않는다.
- `네이밍 - CSharp.md`처럼 제목과 세부 대상을 구분하는 공백을 둔 하이픈은 사용할 수 있다.
- `README.md`, `AGENTS.md`, `CHANGELOG.md`, `LICENSE.md`처럼 정해진 역할을 가진 파일명은 그대로 사용한다.

번호 규칙은 파일명에 적용한다. 문서 본문의 최상위 제목은 기존 `# 제목` 형식을 사용한다.

## 제목 사용

문서의 첫 줄은 `# 제목` 형식을 기본으로 한다.

예:

```markdown
# 문서 양식
```

제목은 문서가 설명하는 대상을 짧게 드러내야 한다.

## 소항목 사용

본문의 첫 소항목은 `##`로 시작한다.

예:

```markdown
## 목적

## 기본 원칙

## 사용 방법
```

`##` 아래에서 세부 기준이 필요하면 `###`를 사용한다.

예:

```markdown
## 사용 방법

### 제목 작성

### 본문 작성
```

`###` 아래에서 다시 세부 항목이 필요할 때만 `####`를 사용한다. 단순히 강조하거나 문단을 나누기 위한 용도로 제목 단계를 늘리지 않는다.

## 제목 주변 빈 행

제목은 다른 제목이나 본문과 바로 붙이지 않는다.

제목 위와 아래에는 빈 행을 한 줄 둔다. 단, 문서의 첫 줄에 있는 `# 제목` 위에는 빈 행을 두지 않는다.

예:

```markdown
# 제목

## 목적

이 문서가 무엇을 설명하는지 적는다.

## 기본 원칙
```

아래처럼 제목과 본문을 붙여 쓰지 않는다.

```markdown
## 목적
이 문서가 무엇을 설명하는지 적는다.
```

제목이 다른 제목 바로 다음에 올 때도 두 제목 사이에는 빈 행을 둔다.

예:

```markdown
## 사용 방법

### 제목 작성
```

## 단계 순서

제목 단계는 아래 순서로 사용한다.

1. `#`: 문서 제목
2. `##`: 본문의 큰 소항목
3. `###`: `##` 아래의 세부 소항목
4. `####`: `###` 아래의 더 작은 세부 소항목

아래처럼 단계를 건너뛰지 않는다.

```markdown
# 제목

### 잘못된 소항목
```

위 구조는 `##`가 빠져 있으므로 피한다. 같은 내용은 아래처럼 작성한다.

```markdown
# 제목

## 소항목

### 세부 소항목
```

## 목록과 목차

이 절은 마크다운(Markdown) 문서의 목록과 목차를 기준으로 작성되었다. 한글·영문 등 문서 언어와 관계없이 같은 기준을 사용하며, 마크다운 템플릿과 예시에도 적용한다.

목록은 항목의 순서와 포함 관계를 표현하고, 목차는 본문의 구성을 안내한다.

- 순서가 있는 항목은 번호 목록을, 단순 나열은 `-` 목록을 사용한다.
- 하위 목록은 상위 목록 항목보다 공백 4칸을 더 들여쓴다. 목록 들여쓰기에 탭을 사용하지 않으며, 같은 계층의 항목은 들여쓰기 위치를 일치시킨다.
- 목차의 최상위 항목과 첫 하위 목록 사이는 빈 줄 한 줄로 구분한다. 그보다 깊은 계층의 상위 항목과 하위 목록은 빈 줄 없이 이어서 작성한다.
- 같은 묶음의 짧은 항목은 빈 줄 없이 이어서 작성한다.
- 상위 항목과 그 하위 목록으로 이루어진 묶음 사이는 빈 줄 한 줄로 구분한다. 하위 목록이 붙은 항목의 묶음에도 같은 기준을 적용한다.
- 목록 안에서 계층이 이어지는 빈 줄은 다음 하위 목록 항목이나 같은 항목의 설명 문단과 같은 깊이로 들여쓴다. 같은 하위 계층의 묶음 사이에도 적용한다. 최상위 항목이나 목록 밖 본문으로 돌아가는 빈 줄에는 공백을 넣지 않는다.
- 이 빈 줄의 공백은 Obsidian 편집 화면의 들여쓰기 안내선이 이어지도록 유지한다. 공백을 일괄 정리할 때도 제거하지 않는다.
- 목차의 항목은 본문의 제목, 절 번호, 계층과 일치시킨다. 문서 구조를 파악하는 데 필요한 깊이까지 수록하되, 중간 계층을 건너뛰지 않는다.
- 절 번호가 있는 문서의 목차는 최상위를 번호 목록으로 작성하고, 하위 항목은 `-` 목록에 본문의 절 번호를 함께 적는다.
- 절 번호가 없는 문서의 목차는 `-` 목록으로 제목과 계층을 표현한다. 일반 목록에 목차의 `1-1` 같은 절 번호 형식을 요구하지 않는다.
- 목차는 제목 앵커 링크 없이 목록으로 작성한다.

절 번호가 있는 목차의 예시이다.

```markdown
1. 들어가며
    
    - 1-1. 적용 기준
    - 1-2. 규칙 강도

2. 코드 컨벤션
    
    - 2-1. 명명 컨벤션
        - 2-1-1. 기준
        - 2-1-2. 기본 명명 규칙
    
    - 2-2. 구조 컨벤션
        - 2-2-1. 영역 구분 규칙
        - 2-2-2. 빈 줄 규칙
```

## 작성 예시

기본 문서 양식은 아래와 같다.

```markdown
# 제목

## 목적

이 문서가 무엇을 설명하는지 적는다.

## 기본 원칙

- 주요 기준을 짧게 나열한다.
- 필요하면 본문에서 자세히 설명한다.

## 사용 방법

문서를 읽는 사람이 실제로 따라야 할 흐름을 단계적으로 설명한다.

### 세부 기준

큰 소항목 안에서 더 작은 기준이 필요할 때 사용한다.

## 검증 기준

- 제목이 `#` 하나로 시작하는가
- 본문 소항목이 `##`부터 시작하는가
- 제목과 다른 제목 또는 본문 사이에 빈 행이 한 줄 있는가
- 파일이 개행 문자로 끝나는가
- 제목 단계를 건너뛰지 않았는가
```

## 호환 링크 형식

GitHub, Obsidian, 일반 Markdown 뷰어에서 문서가 같은 방식으로 읽히도록 링크는 호환 가능한 Markdown 또는 HTML 형식으로 작성한다.

문서 링크는 Obsidian 전용 위키 링크인 `[[문서명]]` 대신 Markdown 링크를 사용한다.

예:

```markdown
[네이밍](네이밍.md)
```

같은 저장소 안의 문서, 이미지, 라이선스, README는 상대 경로로 연결한다. 로컬 컴퓨터의 절대 경로나 특정 편집기 전용 URI를 사용하지 않는다.

특정 제목을 가리키는 앵커 링크(`[...](#제목)`)는 사용하지 않는다. 공백이나 문장부호가 있는 제목은 GitHub과 Obsidian이 만드는 앵커 형식이 달라 한쪽에서만 동작한다. 목차는 링크 없는 목록으로 작성하고, 다른 문서의 특정 절은 파일 단위로 연결한 뒤 절 이름을 본문에 적는다.

예:

```markdown
[네이밍](네이밍.md)의 저장소 이름 절을 참고한다.
```

이미지 임베드는 HTML `<img>` 태그를 사용한다. 폭 힌트가 필요하면 `width` 속성으로 보존한다.

예:

```html
<img src="Resources/image.png" alt="image" width="400">
```

외부 저장소나 외부 문서를 가리킬 때만 `https://...` 링크를 사용한다.

## 검증 기준

마크다운 문서를 새로 작성하거나 수정할 때는 아래를 확인한다.

- 번호가 필요한 파일명은 `00. 제목.md`, 필요 없는 파일명은 `제목.md` 형식인가
- 파일명에서 단어를 하이픈으로 잇는 케밥 표기를 사용하지 않았는가
- 첫 줄이 `# 제목` 형식인가
- 하나의 문서에 `#` 제목이 하나만 있는가
- 본문의 큰 소항목이 `##`부터 시작하는가
- 세부 소항목이 `###`, `####`처럼 단계적으로 내려가는가
- `#`에서 바로 `###`로 넘어가는 등 제목 단계를 건너뛰지 않았는가
- 제목과 다른 제목 또는 본문 사이에 빈 행이 한 줄 있는가
- 파일이 개행 문자로 끝나는가
- 제목 단계를 글자 크기나 강조 용도로 사용하지 않았는가
- 하위 목록을 계층마다 공백 4칸씩 들여쓰고, 탭을 사용하지 않았는가
- 목차에서 하위 목록으로 내려갈 때는 최상위 항목 아래에만 빈 줄 한 줄을 두었는가
- 목록 안에서 계층이 이어지는 빈 줄은 다음 항목이나 설명 문단과 같은 깊이로 들여쓰고, 최상위나 목록 밖으로 돌아가는 빈 줄은 공백 없이 두었는가
- 같은 묶음의 짧은 항목은 붙이고, 하위 목록이 딸린 묶음 사이는 빈 줄 한 줄로 구분했는가
- 목차의 제목·절 번호·계층이 본문과 일치하며, 중간 계층을 건너뛰지 않았는가
- 문서 링크가 `[[...]]`가 아니라 `[](...md)` 형식인가
- 제목 앵커 링크(`[...](#제목)`)를 사용하지 않았는가
- 이미지 임베드가 `![[...]]`가 아니라 `<img src="..." alt="...">` 형식인가
- 저장소 안의 문서와 이미지는 절대 경로가 아니라 상대 경로로 연결되어 있는가
