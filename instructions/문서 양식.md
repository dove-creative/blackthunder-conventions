# 문서 양식

## 목적

이 문서는 마크다운 문서를 작성할 때 문서의 구조와 표기 방식의 기준을 정리한다.

문서의 제목 단계는 독자가 내용을 훑는 순서를 만든다. 따라서 제목은 문서 전체의 이름을 나타내는 `#` 하나로 시작하고, 본문 소항목은 `##`부터 단계적으로 내려가며 사용한다.

## 기본 원칙

- 마크다운 문서는 파일마다 하나의 `# 제목`으로 시작한다.
- `#` 제목은 문서 전체를 대표하는 이름으로 사용한다.
- 본문의 큰 소항목은 `##`부터 사용한다.
- 더 작은 소항목이 필요할 때만 `###`, `####`처럼 한 단계씩 내려간다.
- 제목 단계를 건너뛰지 않는다.
- 제목과 다른 제목 또는 본문 사이에는 빈 행을 한 줄 둔다.
- 파일은 개행 문자로 끝낸다.
- 제목 단계는 글자 크기 조절 용도가 아니라 문서 구조 표현 용도로 사용한다.

## 제목 사용

문서의 첫 줄은 `# 제목` 형식을 기본으로 한다.

예:

```markdown
# 문서 양식
```

제목은 문서가 설명하는 대상을 짧게 드러내야 한다.

## 소항목 사용

본문의 첫 소항목은 `##`로 시작한다.

예:

```markdown
## 목적

## 기본 원칙

## 사용 방법
```

`##` 아래에서 세부 기준이 필요하면 `###`를 사용한다.

예:

```markdown
## 사용 방법

### 제목 작성

### 본문 작성
```

`###` 아래에서 다시 세부 항목이 필요할 때만 `####`를 사용한다. 단순히 강조하거나 문단을 나누기 위한 용도로 제목 단계를 늘리지 않는다.

## 제목 주변 빈 행

제목은 다른 제목이나 본문과 바로 붙이지 않는다.

제목 위와 아래에는 빈 행을 한 줄 둔다. 단, 문서의 첫 줄에 있는 `# 제목` 위에는 빈 행을 두지 않는다.

예:

```markdown
# 제목

## 목적

이 문서가 무엇을 설명하는지 적는다.

## 기본 원칙
```

아래처럼 제목과 본문을 붙여 쓰지 않는다.

```markdown
## 목적
이 문서가 무엇을 설명하는지 적는다.
```

제목이 다른 제목 바로 다음에 올 때도 두 제목 사이에는 빈 행을 둔다.

예:

```markdown
## 사용 방법

### 제목 작성
```

## 단계 순서

제목 단계는 아래 순서로 사용한다.

1. `#`: 문서 제목
2. `##`: 본문의 큰 소항목
3. `###`: `##` 아래의 세부 소항목
4. `####`: `###` 아래의 더 작은 세부 소항목

아래처럼 단계를 건너뛰지 않는다.

```markdown
# 제목

### 잘못된 소항목
```

위 구조는 `##`가 빠져 있으므로 피한다. 같은 내용은 아래처럼 작성한다.

```markdown
# 제목

## 소항목

### 세부 소항목
```

## 작성 예시

기본 문서 양식은 아래와 같다.

```markdown
# 제목

## 목적

이 문서가 무엇을 설명하는지 적는다.

## 기본 원칙

- 주요 기준을 짧게 나열한다.
- 필요하면 본문에서 자세히 설명한다.

## 사용 방법

문서를 읽는 사람이 실제로 따라야 할 흐름을 단계적으로 설명한다.

### 세부 기준

큰 소항목 안에서 더 작은 기준이 필요할 때 사용한다.

## 검증 기준

- 제목이 `#` 하나로 시작하는가
- 본문 소항목이 `##`부터 시작하는가
- 제목과 다른 제목 또는 본문 사이에 빈 행이 한 줄 있는가
- 파일이 개행 문자로 끝나는가
- 제목 단계를 건너뛰지 않았는가
```

## 호환 링크 형식

GitHub, Obsidian, 일반 Markdown 뷰어에서 문서가 같은 방식으로 읽히도록 링크는 호환 가능한 Markdown 또는 HTML 형식으로 작성한다.

문서 링크는 Obsidian 전용 위키 링크인 `[[문서명]]` 대신 Markdown 링크를 사용한다.

예:

```markdown
[네이밍](네이밍.md)
```

같은 저장소 안의 문서, 이미지, 라이선스, README는 상대 경로로 연결한다. 로컬 컴퓨터의 절대 경로나 특정 편집기 전용 URI를 사용하지 않는다.

특정 제목을 가리키는 앵커 링크(`[...](#제목)`)는 사용하지 않는다. 공백이나 문장부호가 있는 제목은 GitHub과 Obsidian이 만드는 앵커 형식이 달라 한쪽에서만 동작한다. 목차는 링크 없는 목록으로 작성하고, 다른 문서의 특정 절은 파일 단위로 연결한 뒤 절 이름을 본문에 적는다.

예:

```markdown
[네이밍](네이밍.md)의 저장소 이름 절을 참고한다.
```

이미지 임베드는 HTML `<img>` 태그를 사용한다. 폭 힌트가 필요하면 `width` 속성으로 보존한다.

예:

```html
<img src="Resources/image.png" alt="image" width="400">
```

외부 저장소나 외부 문서를 가리킬 때만 `https://...` 링크를 사용한다.

## 검증 기준

마크다운 문서를 새로 작성하거나 수정할 때는 아래를 확인한다.

- 첫 줄이 `# 제목` 형식인가
- 하나의 문서에 `#` 제목이 하나만 있는가
- 본문의 큰 소항목이 `##`부터 시작하는가
- 세부 소항목이 `###`, `####`처럼 단계적으로 내려가는가
- `#`에서 바로 `###`로 넘어가는 등 제목 단계를 건너뛰지 않았는가
- 제목과 다른 제목 또는 본문 사이에 빈 행이 한 줄 있는가
- 파일이 개행 문자로 끝나는가
- 제목 단계를 글자 크기나 강조 용도로 사용하지 않았는가
- 문서 링크가 `[[...]]`가 아니라 `[](...md)` 형식인가
- 제목 앵커 링크(`[...](#제목)`)를 사용하지 않았는가
- 이미지 임베드가 `![[...]]`가 아니라 `<img src="..." alt="...">` 형식인가
- 저장소 안의 문서와 이미지는 절대 경로가 아니라 상대 경로로 연결되어 있는가
