# 이전 변경 이력

이 문서는 규칙 ID 초기화 이전의 변경 이력을 보관한다. 여기의 규칙 ID는 초기화 이전 번호이며, 현재 번호는 [변경 이력](../CHANGELOG.md)의 대응표에서 확인한다.

## 기록 기준

- 최신 날짜를 위에 둔다.
- 날짜 아래는 `추가`, `변경`, `삭제`로 나누고, 해당하는 항목만 둔다.
- 규칙 ID가 있으면 항목 앞에 적고, 대상 문서를 괄호로 밝힌다.
- 기존 코드나 문서를 맞춰야 한다면 그 방법을 항목에 함께 적는다.
- 오탈자 수정처럼 규칙의 의미가 바뀌지 않는 변경은 기록하지 않는다.

## 2026-11-07

### 추가

- 목록과 목차(문서 양식): 마크다운(Markdown) 문서에 적용하는 규칙임을 명시하고, 한글·영문 등 문서 언어와 관계없이 같은 기준을 사용한다. 하위 목록은 계층마다 공백 4칸을 들여쓰고 탭을 사용하지 않는다. 같은 묶음의 짧은 항목은 붙여 쓰고, 하위 목록이 딸린 묶음 사이는 빈 줄 한 줄로 구분한다. 목차는 본문의 제목·절 번호·계층에 맞춰 링크 없는 목록으로 작성하고, 최상위 항목과 첫 하위 목록 사이에도 빈 줄 한 줄을 둔다. 목록 안에서 계층이 이어지는 빈 줄은 다음 항목이나 설명 문단의 들여쓰기를 유지하여 Obsidian의 들여쓰기 안내선이 이어지도록 한다. 최상위 항목이나 목록 밖 본문으로 돌아가는 빈 줄에는 공백을 넣지 않는다. 이 저장소의 마크다운 문서와 마크다운 템플릿 예시에도 적용한다.
- 문서 파일명(문서 양식): 번호가 필요한 문서는 `00. 제목.md`, 필요 없는 문서는 `제목.md` 형식을 사용한다. 단어는 공백으로 구분하고 케밥 표기는 사용하지 않는다. 세부 대상을 구분하는 공백을 둔 하이픈과 README 등 정해진 역할의 파일명은 유지하며, 본문의 최상위 제목은 `# 제목` 형식을 사용한다. 기존 문서 파일명을 변경할 때는 참조 링크와 경로도 함께 갱신한다.
- Python 컨벤션: Python에 적용되는 공통 규칙을 같은 `COM` ID로 수록한 언어별 문서를 추가하고, README와 AGENTS 안내에서 연결한다. `COM-REGION-01`~`COM-REGION-05`와 `COM-BLANK-02`·`COM-BLANK-03`·`COM-BLANK-04`·`COM-BLANK-06`은 Python에 적용하지 않으며, 공통 컨벤션을 참조할 때도 적용하지 않는다. 공통·C#·TypeScript의 규칙은 유지한다.
- `PY-STYLE-01`(Python): 프로젝트 지침·설정과 본 컨벤션에서 별도로 정한 규칙 외에는 PEP 8을 따른다.
- `PY-REGION-01`(Python): 멤버를 역할별로 모아 배치한다. 기존 코드는 해당 코드를 수정할 때 역할별 묶음 중심으로 정리한다.
- `PY-REGION-02`(Python): 이름과 배치만으로 역할 구분이 어려울 때 영어 영역 주석을 사용할 수 있다. 고정 영역 이름과 장식용 구분선은 요구하지 않는다.
- `PY-BLANK-01`(Python): 모듈 최상위 함수·클래스 정의의 앞뒤는 빈 줄 두 줄로, 클래스 안의 메서드 정의 사이는 빈 줄 한 줄로 구분한다. 정의의 간격에는 일반적인 논리적 묶음보다 이 간격을 우선하며, 기존 코드는 해당 코드를 수정할 때 함께 맞춘다.
- `PY-BLANK-01.1`(Python): 더미 구현처럼 밀접하게 관련된 한 줄 함수·메서드 정의의 묶음은 정의 사이의 빈 줄을 생략할 수 있다. `@overload` 같은 데코레이터 줄은 줄 수에 포함하지 않는다. 여러 줄 메서드를 역할이 같다는 이유만으로 붙이던 경우에는 해당 코드를 수정할 때 `PY-BLANK-01`의 간격을 적용한다.
- `PY-BLANK-02`(Python): `COM-BLANK-05`의 제어문에는 `if`·`for`·`while`·`try`·`with`·`match`를 포함한다. `elif`·`else`·`except`·`finally`는 앞선 문과 하나의 제어문으로 본다. 기존 코드는 해당 코드를 수정할 때 함께 맞춘다.
- `PY-BLANK-02.1`(Python): 본문이 한 줄의 단순 문장이고 `elif`·`else`가 없는 `if`는 `COM-BLANK-05`의 한 줄 `if`로 보고 서로 붙여 쓸 수 있다.
- `PY-WRAP-01`(Python): 코드, 주석, docstring의 한 줄 길이는 120자를 넘지 않도록 한다. PEP 8의 79자·72자 제한 대신 이 기준을 적용한다. 기존 코드는 해당 코드를 수정할 때 함께 맞춘다.
- `PY-QUOTE-01`(Python): 문자열 리터럴은 큰따옴표(`"`)를 기본으로 하며, 불필요한 이스케이프를 줄여 가독성을 높일 때는 작은따옴표를 사용할 수 있다. 기존 코드는 해당 코드를 수정할 때 함께 맞춘다.
- `PY-QUOTE-02`(Python): 주석이나 문자열 내용 안의 인용은 작은따옴표(`'`)를 기본으로 한다. docstring 내용에도 적용하되, 원문이나 데이터·코드의 정확한 표기를 보존해야 할 때는 예외로 한다. 기존 코드는 해당 코드를 수정할 때 함께 맞춘다.
- `PY-QUOTE-03`(Python): docstring과 그 밖의 삼중 따옴표 문자열은 삼중 큰따옴표(`"""`)로 감싼다. 한 줄 docstring에도 적용하며, 기존 코드는 해당 코드를 수정할 때 함께 맞춘다.

## 2026-11-06

### 추가

- `COM-BLANK-05`(공통, C#, TypeScript): 제어문의 앞뒤에는 빈 줄 한 줄을 두되, 블록의 시작과 끝에는 두지 않는다. `if`와 `else`는 하나의 제어문으로 본다. 제어문과 직접 연관된 선언은 제어문의 일부로 보고 붙여 쓸 수 있으며, 이때 빈 줄은 선언 위에 둔다. `else` 없는 한 줄 `if`가 이어지면 서로 붙여 쓸 수 있다. 기존 코드는 해당 코드를 수정할 때 함께 맞춘다.
- `COM-BLANK-01.1`(공통, C#, TypeScript): 진입부와 진출부는 본문과 별도의 논리로 보고 빈 줄 한 줄로 구분할 수 있다. 진입부는 조기 반환 검사와 그에 바로 딸린 상태 변경이며, 그 안에서는 제어문 뒤의 빈 줄을 생략할 수 있다. 진출부는 마지막 반환이다. 코드가 짧거나 흐름이 명확하면 구분을 생략할 수 있다.
- `COM-BLANK-06`(공통, C#, TypeScript): 객체 초기화나 여러 줄 람다처럼 중괄호 블록이 있는 문장의 앞뒤에는 빈 줄 한 줄을 두되, 블록의 시작과 끝에는 두지 않는다. 기존 코드는 해당 코드를 수정할 때 함께 맞춘다.
