## 1. 들어가며

이 문서는 작성자 dove가 여러 언어의 코드에 공통으로 적용하는 명명과 구조의 기준을 정리한 것이다. 구체적인 문법과 서식은 해당 언어의 컨벤션에서 다룬다.

### 1-1. 적용 기준

- 적용 우선순위는 프로젝트 지침·설정 → 언어별 컨벤션 → 공통 컨벤션이다.
- 언어별 문서에는 해당 언어에 적용되는 공통 규칙도 함께 수록한다. C# 작업은 [C# 컨벤션](02.%20dove%20CSharp%20convention.md), TypeScript 작업은 [TypeScript 컨벤션](02.%20dove%20TypeScript%20convention.md)을 기본 문서로 읽는다.
- 이 문서는 언어 간 공통 기준을 관리하는 문서이다. 공통 규칙을 변경할 때는 언어별 문서에서 같은 ID를 가진 항목도 함께 갱신한다.
- 각 규칙은 해당하는 코드 구조에 적용한다. 클래스의 영역 구분과 생애주기 배치를 모든 모듈에 동일하게 요구하지 않는다.
- 언어별 대소문자, 접두사, 중괄호와 구체적인 줄바꿈 방식은 해당 언어의 컨벤션에서 정한다.

### 1-2. 규칙 강도

| 강도 | 의미 |
|---|---|
| Must | 반드시 준수한다. |
| Should | 특별한 이유가 없다면 준수한다. |
| May | 상황과 의도에 따라 선택할 수 있다. |
| Must Not | 사용하지 않는다. |
| Should Not | 특별한 이유가 없다면 사용하지 않는다. |

### 1-3. 규칙 표기

- 규칙은 `ID`, `강도`, `규칙` 열을 가진 표로 작성한다.
- ID는 `범위-분류-번호` 형식이다. 예: `COM-BLANK-02`
- 범위는 공통 규칙이 `COM`, C# 전용 규칙이 `CS`, TypeScript 전용 규칙이 `TS`이다. 언어별 문서에 수록한 공통 규칙은 이 문서와 같은 `COM` ID를 사용한다.
- 규칙에 딸린 짧은 설명과 예시는 같은 칸에 적는다. 코드 예시는 표 아래에 두고, 어떤 규칙의 예시인지 ID로 밝힌다.
- 한 번 부여한 ID는 규칙의 위치가 바뀌어도 유지하고, 삭제한 규칙의 ID는 재사용하지 않는다. 새 규칙에는 같은 분류의 마지막 번호 다음 번호를 붙인다.

## 2. 코드 컨벤션

### 2-1. 명명 컨벤션

#### 2-1-1. 기준

식별자 이름은 해당 요소의 핵심 역할이 바로 드러나도록 짓는다.

#### 2-1-2. 구체적인 이름 사용

| ID | 강도 | 규칙 |
|---|---|---|
| COM-NAME-01 | Should | 숫자나 모호한 이름보다, 의미가 드러나는 구체적인 이름을 우선한다. |

### 2-2. 구조 컨벤션

#### 2-2-1. 영역 구분 규칙

| ID | 강도 | 규칙 |
|---|---|---|
| COM-REGION-01 | Should | 멤버를 역할별로 묶고 영어 주석으로 영역을 구분한다. |
| COM-REGION-02 | May | 메서드가 많으면 `Content - Public`, `Content - Internal` 등으로 영역을 세분화할 수 있다. |
| COM-REGION-03 | May | 코드가 짧으면 영역 구분 주석을 생략할 수 있다. |

아래 이름은 클래스의 영역 구성 예시이며, 모든 객체나 모듈에 동일한 이름이나 구성을 강제하지 않는다.

| 영역 예시 | 의미 |
|---|---|
| `Front` | 공개 멤버 |
| `Property` | 도메인 객체가 사용하지 않는 공개 멤버 |
| `Internal` | private 필드 |
| `Content` | 생성자와 메서드 |

#### 2-2-2. 빈 줄 규칙

| ID | 강도 | 규칙 |
|---|---|---|
| COM-BLANK-01 | Should | 일반적인 논리적 묶음이나 영역 사이는 빈 줄 한 줄로 구분한다. |
| COM-BLANK-02 | Should | 멤버 선언 영역과 `Content` 영역 사이는 빈 줄 두 줄로 구분한다. |
| COM-BLANK-03 | May | 코드가 짧으면 멤버 선언 영역과 `Content` 영역 사이를 빈 줄 한 줄로 구분할 수 있다. |
| COM-BLANK-04 | May | 밀접하게 연관된 멤버, 오버로드, 단축 메서드 등 같은 역할을 하는 메서드는 빈 줄 없이 이어서 작성할 수 있다. |

멤버 선언 영역과 `Content` 영역 사이의 간격은 해당 영역 구성을 사용하는 경우에 적용한다. C#의 구체적인 배치는 [C# 컨벤션](02.%20dove%20CSharp%20convention.md)의 빈 줄 규칙 예시를 참고한다.

#### 2-2-3. 메서드 배치 규칙

| ID | 강도 | 규칙 |
|---|---|---|
| COM-ORDER-01 | Should | 메서드는 가능한 한 생애주기 순서로 배치한다. |
| COM-ORDER-02 | Should | 같은 생애주기 단계에서는 논리적으로 관련된 기능끼리 묶어 배치한다. |
| COM-ORDER-03 | Should | 각 기능 묶음 안에서는 사용 흐름에 따라 배치한다. |

생애주기 순서는 생성·사용·정리 단계가 있는 대상에 적용한다. 배치 기준은 다음과 같이 큰 흐름에서 세부 흐름으로 적용한다.

1. **생애주기 순서**: 생성·초기화 → 일반 동작 → 정리 순서로 배치한다.
2. **논리 순서**: 같은 생애주기 단계의 메서드를 관련 기능별로 묶어 배치한다. 예: 노드 관리 → 세그먼트 관리.
3. **사용 흐름**: 각 기능 묶음 안에서 기능을 사용하는 일반적인 절차에 따라 배치한다. 예: 등록 → 조회 → 삭제.

생애주기 단계가 없는 함수 중심 모듈에는 논리적 묶음과 사용 흐름에 따른 배치 원칙을 적용한다. C#의 구체적인 배치는 [C# 컨벤션](02.%20dove%20CSharp%20convention.md)의 메서드 배치 규칙 예시를 참고한다.
